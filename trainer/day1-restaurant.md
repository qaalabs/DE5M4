# User Story Examples for the Restaurant Website Lab

To help your learners understand how to create effective user stories, epics, and backlog items for the restaurant website scenario, here are examples for each level of the Agile hierarchy:

## Epic Examples

Epics represent larger features that can be broken down into multiple user stories:

1. **Restaurant Brand Identity**
   - This epic covers all aspects of establishing the restaurant's visual identity including logo design and consistent branding across the website.

2. **Customer Website Navigation**
   - This epic includes all features related to how customers move between different parts of the website.

3. **Online Ordering System**
   - This epic encompasses the entire online food ordering capability.

4. **Reservation Management System**
   - This epic covers the full table reservation functionality for both customers and staff.

5. **Restaurant Information Display**
   - This epic includes all informational content about the restaurant including location, about us, and contact details.

## User Story Examples

Here are user stories that would fall under these epics:

### Epic: Restaurant Brand Identity

1. **As a customer**, I want to see a consistent leaf-themed logo throughout the website, so that I can easily identify the restaurant's vegan brand.

2. **As a business owner**, I want the logo to appear in the website tab, so that customers can identify our site when multiple tabs are open.

3. **As a marketing manager**, I want social media links displayed on the website, so that customers can follow and engage with us on different platforms.

### Epic: Customer Website Navigation

4. **As a customer**, I want a clear navigation menu, so that I can easily switch between different sections of the website.

5. **As a mobile user**, I want the website to be responsive, so that I can navigate it comfortably on my smartphone.

6. **As a first-time visitor**, I want intuitive menu categories, so that I can quickly find what I'm looking for without confusion.

### Epic: Online Ordering System

7. **As a hungry customer**, I want to view the complete menu with prices, so that I can decide what to order.

8. **As a customer with dietary restrictions**, I want to see detailed descriptions of each menu item, so that I can make informed choices.

9. **As a customer**, I want to select multiple items to add to my cart, so that I can place a complete order.

10. **As a customer**, I want to specify pickup or delivery options, so that I can receive my food in my preferred way.

### Epic: Reservation Management System

11. **As a customer**, I want to see which tables are available on specific dates, so that I can make a reservation that suits my schedule.

12. **As a customer**, I want to receive confirmation of my reservation, so that I can be confident my table is booked.

13. **As a restaurant staff member**, I want to view all reservations in a calendar format, so that I can manage seating effectively.

14. **As a restaurant staff member**, I want to update or cancel reservations, so that I can accommodate changes requested by phone.

### Epic: Restaurant Information Display

15. **As a customer**, I want to see the restaurant's exact location with address details, so that I can find it easily.

16. **As a potential customer**, I want to learn about veganism on the About Us page, so that I can understand the restaurant's philosophy.

17. **As a customer**, I want to see pictures of the restaurant's cuisine, so that I can get excited about dining there.

18. **As a customer**, I want to see information about the head chefs, so that I can appreciate the expertise behind the menu.

## Task Examples

Tasks are smaller, technical work items that contribute to completing a user story:

### For the story: "As a customer, I want to see a consistent leaf-themed logo throughout the website"

1. Design 3-5 logo concepts with leaf theme
2. Gather stakeholder feedback on logo concepts
3. Finalize logo design based on feedback
4. Create logo in multiple formats (PNG, SVG, favicon)
5. Implement logo in navbar component
6. Implement logo in website footer
7. Add logo to browser tab as favicon
8. Test logo display across different browsers and devices

### For the story: "As a customer, I want to see which tables are available on specific dates"

1. Design database schema for storing table information and availability
2. Create API endpoint to retrieve available tables by date
3. Develop calendar UI component for date selection
4. Implement table availability visualization
5. Create booking form component
6. Connect form to reservation API
7. Add validation for 1-month advance booking limitation
8. Test reservation system with multiple scenarios

## MoSCoW Prioritization Example

Here's how you might prioritize the first sprint items using MoSCoW:

### Must Have

- Logo design and implementation (brand identity)
- Basic navigation menu structure
- About Us page with restaurant information
- Contact page with location information
- View-only menu page with items, descriptions and prices

### Should Have

- Social media links
- Mobile responsiveness
- Chef information on About Us page
- Images of vegan cuisine

### Could Have

- Table reservation view functionality (without booking capability yet)
- Basic contact form

### Won't Have (for Sprint 1)

- Online ordering functionality
- Reservation management for staff
- Payment processing
- User accounts/login

## First Sprint Backlog Example

Here's an example of what could go into Sprint 1 (assuming 2-week sprint):

1. Design and implement leaf-themed logo across website (Est: 8 points)
2. Create responsive navigation menu with links to all main pages (Est: 5 points)
3. Develop About Us page with veganism information and chef profiles (Est: 5 points)
4. Build Menu page with item listings, descriptions and prices (Est: 8 points) 
5. Create Contact Us page with restaurant location and map (Est: 3 points)
6. Implement social media links in footer (Est: 2 points)
7. Set up basic website hosting and deployment pipeline (Est: 5 points)

These examples provide a comprehensive model that demonstrates the hierarchy from epics down to specific tasks, along with prioritization and sprint planning for the restaurant website scenario. They showcase the proper format for user stories while connecting directly to the requirements in the lab document.
