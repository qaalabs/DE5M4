# Every cloud data pipeline needs four things

| Building block | What it does |
|----------------|--------------|
| **Storage**        | Keep the data somewhere (files, databases, data lakes) |
| **Compute**        | Process and transform it (VMs, containers, serverless) |
| **Integration**    | Move it between systems (queues, APIs, event streams) |
| **Orchestration**  | Coordinate when and how it all runs (schedulers, pipelines) |

These four categories cover the vast majority of what a data engineer builds with.

---

# Why AWS, Azure, and GCP?

These three own around **two-thirds of the global cloud market**:

- **AWS** (Amazon) - the original, widest service catalogue, ~33% market share
- **Azure** (Microsoft) - dominant in enterprise, Active Directory and Office 365
- **GCP** (Google) - strong data and ML tooling (BigQuery, Dataflow, Vertex AI)

Note:
Databricks runs *on top of* AWS, Azure, or GCP - it is a platform, not a cloud provider. You will still need one of these three underneath it.

Oracle Cloud exists, but its market share is small and it is mainly used by companies already deep in Oracle's database ecosystem.

If your employer uses one of these three, the concepts transfer directly.
