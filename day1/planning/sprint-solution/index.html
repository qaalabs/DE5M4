    Sptint Planning ~ Possible solution

    Sample Sprint Planning Outcome

    Help learners understand what good sprint planning looks like:

    Sprint 1 Goal

    Deliver a basic restaurant website where customers can learn about the restaurant and contact them.

    Selected User Stories (Example)

    • Display restaurant logo consistently (2 points)
    • Show restaurant address and contact info (1 point)
    • Create basic navigation menu (3 points)
    • Display About Us content explaining veganism (3 points)
    • Show menu items with descriptions and prices (5 points)
    • Display social media links (2 points)
    • Create basic contact page (3 points)
    • Total: 19 points (leaving room for unexpected work)

    Stories Moved to Later Sprints

    • Online ordering system (13 points) - Sprint 2
    • Reservation management (8 points) - Sprint 2
    • Staff reservation tools (8 points) - Sprint 3

    Key Learning Points to Emphasise

    During the activity, guide learners to consider:

    1. Capacity Management: "Don't pack the sprint completely full - leave buffer for unexpected work"

    2. Value Focus: "Choose stories that deliver real user value, not just technical tasks"

    3. Dependencies: "Consider what must be built first vs. what can be done in parallel"

    4. Definition of Done: "What does 'complete' mean for each story?"

    5. Risk Management: "What could go wrong and how would you handle it?"

    Connection to Data Engineering

    In your data engineering projects, Sprint 1 might include:

    • Set up basic data pipeline infrastructure
    • Implement initial data source connections
    • Create simple data validation checks
    • Deliver first basic reports to stakeholders

    The same principles apply - focus on delivering working functionality that provides real value, while building the foundation for future sprints.

    Wrap-up

    Sprint planning is about making realistic commitments that your team can deliver. It's better to under-promise and over-deliver than to overcommit and disappoint stakeholders. The goal is sustainable pace and predictable delivery.

    This activity gives learners practical experience with the sprint planning process while reinforcing the concepts of capacity, prioritisation, and incremental delivery that are central to Agile data engineering projects.
